# Contributing

1. Create a branch from `main`.
2. Keep architecture-impacting changes aligned with an ADR; add a new ADR when the decision or trade-off changes.
3. Run `make ci` before opening a pull request.
4. Add tests for transformation, contract and failure semantics.
5. Never commit credentials, customer data or cloud state.
6. Prefer small, reviewable commits and explain operational impact in the PR.
